How long to wait for each network before trying the next, and how often to look again once the hub has given up and is on its hotspot alone. A shorter retry picks up your home network sooner when you pull onto the drive; a longer one uses less power.

The things to tick off on the van display's Drive page before setting off, one per line — up to 10, each up to 32 characters. The hook-up, the heater, alarms and the battery are checked on their own and do not need listing. The page comes up by itself when the engine starts with anything unticked.
Switch names
The six buttons on the Switches page, in order from top left, up to 14 characters each. Leave one blank to go back to its original name. Each switches the relay of the same number on the hub (on: the relay is energised, COM connected to NO).
Display software
The van display updates itself from the hub: it looks two minutes after it starts and then every hour, and changes over when nobody is using it. If a new version will not start, it goes back to the one before.

Alerts
Safety warnings
Warnings are evaluated on the hub, not in the browser, every poll cycle (about 5 s) from the live device readings, and raised on the first reading that shows the condition — there is no hold-off. Every open page, the van display and the phone app ask the hub every 2 s, so a warning reaches them within seconds. Clear alarm on any of them clears it on all of them; it sounds again the next time the condition arises. Switching a warning off stops it being evaluated at all: no banner and no sound anywhere. Sound below is separate and applies to all of them; the banner always shows regardless.
% charge
Sounds on every screen and phone for up to a minute, so you can check they all go off.
Panic alarm
Sets off the van display's red and blue beacon and siren, and the alarm on every open page and phone. Hold the button for one second so a stray tap cannot set it off. Stop panic in the alert bar, or STOP on the display, stops it everywhere; it stops by itself after 30 minutes.
Display
Panel on the van
The 128×64 OLED beside the hub. It is a monochrome panel — the colour is fixed in the glass and cannot be changed in software — but brightness, which way up it reads and how often it redraws are all set here. Changes take effect on the screen as soon as you save; none of them need a restart.
Brightness
Full brightness is uncomfortable in a dark van at night. There is no zero — a black screen is indistinguishable from a broken one, so use the switch above to turn it off.

seconds

Page layouts
How the Overview and Level pages draw themselves. These are stored on the hub, not in this browser, so a van is set up once and every phone, tablet and laptop that opens it agrees. A change takes effect on the next refresh — no reload needed.
The flow diagram is a wide drawing, and on a phone it scales down until the figures on it cannot be read. Cards shows the same readings as large tiles that stay legible at any width. Automatic picks the diagram on a wide screen and cards on a narrow one, which suits a van that is looked at from both.
Spirit level is the bubble vial: the bubble floats to the high side, so you drive or ramp towards it. Van attitude draws the vehicle from behind and from the side, tilted the way it is actually sitting. Both read the same sensor and the same angles; only the drawing differs.

Sensor orientation
Which way the sensor is fitted. Tilt the van (or the sensor) and flip whichever of these reads backwards — that is quicker and more reliable than working it out from how the board is mounted. These act at the sensor, so the spirit level, the van drawings, the wording and the display all follow together and cannot disagree. The stored zero is kept in the sensor's own axes, so it survives a change here — there is no need to calibrate again afterwards.
 
ms — how often the bubble updates
The Level page polls a small dedicated endpoint, not the whole dashboard, so refreshing quickly is cheap on the network. The floor is 200 ms because each measurement averages 16 samples and takes about 80 ms of the hub's time; asking much faster would spend most of it measuring tilt instead of reading the battery and charger.
Calibration
Park on ground you know to be flat, let the van settle, then set the zero. The sensor is never mounted perfectly square, so this is what makes the readings mean anything. It is stored on the hub. If the sensor is ever moved, calibrate again.
Drift log
A diagnostic, not something to leave running. It records the tilt and the sensor's temperature every few minutes, but only while the van is parked and still, so you can see whether the level wanders as the day warms up. The sensor's zero moves by about 0.06° per °C (measured on this van: docs/level_drift), which over a cold night and a sunny afternoon can come to a degree or more, and no calibration can remove it. Switch it on for a day or two, download the file, then switch it off again — it writes to the hub's flash while it runs.

The vial's scale is deliberately not linear. A rim at 30° would put one degree about 4 pixels from the centre, so the bubble would barely move while you were levelling. The radius follows the square root of the angle instead, which puts one degree roughly six times further out while the rim still reaches the limit above. Each ring is labelled with its angle, because a non-linear scale cannot be read by eye otherwise.
GPS
External receiver
A u-blox NEO-7M (or any NMEA receiver) on a UART, which is how the van knows where it is. The browser cannot help here: its location service needs a secure origin, and this hub is served over plain http, so the Outside page has no position of its own without one. Switch this off and nothing is opened — an unwired receiver should not look like a fault.
Wiring
Four wires. Only the receiver's TX matters for reading position — the hub's TX is wired for configuring the receiver later and can be left off.

The pins live in config.py rather than here: a wrong pin is a receiver that never answers with nothing on screen to say why, so changing them is a deliberate act. The values above are read from the hub, so they are what it is actually using. The pins must belong to the UART chosen there. On the Waveshare relay board the GPS uses UART0 on GPIO0/GPIO1, because UART1 is the board's RS485 port (GPIO24/25); where the pins are is on the board's silkscreen and in docs/HARDWARE.md.
Security
Hub password
With a password set, changing settings, the heater, frost protection, timers, storage mode, guard, the battery's switches and restarting the hub all ask for it — once per phone or browser, which remembers a key worked out from it, never the password. Anyone on the van's WiFi can still see everything, set the lights and use panic. Password required off leaves the hub open again without forgetting the password. Forgotten it? A factory reset (below) clears it, or it can be cleared over USB from a computer.
Factory reset
Starting again from scratch, when the password is forgotten or before passing the van on. No password is needed: having a hand on the board is the permission, as with a router's reset button.
  • The hub: with it running, hold the BOOT button on the board for 10 seconds. From 2 seconds its light flashes red and it beeps each second; at 10 it gives one long beep, clears everything and restarts. Let go before then to cancel.
  • The van display: with it running, hold the BOOT button on the back for 10 seconds. A short press still turns the screen off and on; held, it counts down on the screen from 8. Let go before the end to cancel.
  • Not while switching on. Held while the power is connected, BOOT puts either board into its firmware-loading mode instead: nothing is lost, it just waits. Disconnect and reconnect the power to carry on.
The hub forgets: every setting on these pages (networks, Bluetooth devices and the Victron key, location, alerts, switch names, the checklist), the password and the display's pairing, the levelling calibration, the relays, timers, guard, frost protection and storage mode, and its logs. It keeps its software and config.py, and comes back with the values set there when it was installed, including the hotspot's name and password: to hand on a truly blank hub, replace config.py over USB too.
The display forgets: its pairing with the hub, the networks it learned from the hub, its brightness and sound settings and the game scores, so it shows a code to pair again. It keeps its software, its update key and its touch calibration.
Never expose the hub to the internet
Do not port-forward the hub on a router, or put it behind a tunnel or reverse proxy that makes it reachable from outside. It is built for the van's own WiFi only:
  • No encryption (plain HTTP, no HTTPS): the password key, settings and readings cross the network as readable text.
  • Anyone who can reach it can read everything, set the lights and set off the panic alarm — even with a password set.
  • It controls real equipment: the heater, the relays, and the battery switches that can cut the van's 12 V.
  • It is a small microcontroller: a burst of requests from an internet scanner can stall it.
To see or control the van from away, use a system that reads the hub on the local network and is secured itself, such as Home Assistant.
